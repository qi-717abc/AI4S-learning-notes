## 一、从模型到科研智能体：为什么需要系统？（第 1—5 页）

### 1. AI Scientist 引出了什么问题？

课件第 2 页引用论文 *Towards end-to-end automation of AI research*，用 AI Scientist 作为科研自动化的例子。一个科研任务不只是“回答一个问题”，还可能包含提出想法、安排实验、执行代码、记录结果、生成图表和组织论文等步骤。每一步都有输入、输出和可能出错的地方。

**外部补充**：原论文将 AI Scientist 用于机器学习研究，并讨论了有人工提供初始代码模板的设置和更开放的设置；还包含自动评审。论文所展示的系统和评价具有特定任务、环境和实验条件，不能将其结果理解为在所有科学领域已经独立完成可信科研。[1]

把它和前两讲连起来：前两讲中的神经网络是可训练的预测模型；科研智能体可以在较大的任务中调用模型、检索工具或代码工具。**智能体组织的过程是否合理**，仍取决于问题定义、数据、实验设计和独立验证。

### 2. LLM、Agent、Harness 分别是什么？

- **模型（Model）**：接收输入并产生输出的系统。本课以大语言模型（LLM）为例，它可根据提供的上下文生成文本或结构化的工具请求。模型本身擅长的操作和准确性受训练、输入及具体实现限制。
- **智能体（Agent）**：为了某个目标，根据环境信息选择行动并与环境交互的系统。LLM Agent 是以语言模型为重要决策部件的一类智能体；不是所有 Agent 都必须由 LLM 驱动。
- **运行框架（Harness）**：围绕模型组织任务执行的运行支持部分，例如准备上下文、发起模型调用、协调工具、处理结果、记录状态和执行权限规则。具体系统对 Harness 的划分不一定完全相同。[2]

课件用 **Agent ≈ Model + Harness** 作教学比喻，并明确它不是严格的学术定义（第 12—15 页）。这里“＋”表示把若干部件组织成系统，不是数学上充分且唯一的定义；工具、环境和用户目标也需要考虑。模型做出工具请求，不等于模型自己拥有了工具执行权限。

### 3. 为什么只给大模型一个问题不总是够？

课件第 4—5 页讨论早期使用 LLM 的方式、上下文限制和幻觉。

**上下文**是一次模型调用可接收的任务指令、对话、文档片段及工具结果等信息。可用空间有限：内容太长时，系统可能截断、压缩或选择一部分信息；是否保留跨轮次记录取决于具体产品和运行框架，不能一概说模型会永久记住全部对话。

**幻觉**指生成了看似合理却没有依据、与证据冲突或事实错误的内容。例如，模型可能编出不存在的论文题目或 DOI。检索和外部工具能提供可核对的材料，但检索结果本身也可能过时、错误或被误读；仍需检查来源和原文。

> 示例：让模型“列出某领域所有突破”而不指定时间、数据库和范围，回答可能遗漏文献；给出可执行的检索方案并记录来源，可提高可检查性，但仍不能自动证明检索穷尽。

**理解检查**：为什么把“能够生成论文摘要”直接等同于“已经读过并核实论文”是不成立的？

<details><summary>参考思路</summary>

生成文本并不能证明系统访问过原文或正确提取信息；应检查是否真的获取论文、读取范围是什么，以及结论能否回到具体来源。
</details>

## 二、用“学生学习”类比 Agent 系统（第 6—15 页）

### 4. 一次任务为什么要有过程和反馈？

课件用“家长希望学生考好”来类比目标驱动的过程。第 6—7 页对照理想与现实：**给定目标 ≠ 一定得到期望结果**；第 8—11 页逐步引入上课、练习、考试、教师指导与工具等环节，强调安排步骤和反馈能帮助改进过程。

- **目标**：希望完成什么，例如找到与某主题有关的研究。
- **行动**：选择检索词、查数据库、阅读摘要、检查全文。
- **反馈**：结果是否相关？数据库是否返回错误？来源是否可靠？
- **调整**：修改关键词、查另一来源、记录无法验证的问题。
- **停止**：达到约定范围或出现必须由人处理的阻碍时报告结果。

这一类比突出了智能体系统中的目标、执行步骤和反馈机制。

### 5. 把类比映射到技术部件

课件第 14—15 页将模型与运行支持分开：

| 部件 | 可以怎样理解 | 文献任务中的例子 |
| --- | --- | --- |
| Model | 根据上下文生成回答或下一步请求 | 从结果中判断哪些题名值得进一步核对 |
| Harness | 管理运行状态、工具调用和约束 | 接收请求、检查允许范围、把结果反馈给模型 |
| Tool | 提供可执行的外部能力 | 调用数据库检索、读取 PDF、写入文件 |
| Agent | 面向目标组织模型与行动的系统 | 多轮检索并整理一份可核查的文献清单 |
| 用户／研究者 | 提出问题并判断结果是否可用 | 确定范围、判断证据与结论是否可靠 |

工具返回的数据不会自动成为真实结论：Harness 负责把它传回来，模型负责理解与组织，研究者仍需核查。课件第 13 页还把学校类比为多智能体系统：不同角色可分工，但这只是组织方式，不意味着多 Agent 一定优于单 Agent。

## 三、文献检索中各个部件如何协作（第 16—22 页）

### 6. 逐步看一次单 Agent 检索

课件第 16 页的时序图可以读成下面六步：

```text
① 用户提出任务和边界
         ↓
② Harness 整理任务、工具说明和已有记录，调用模型
         ↓
③ 模型产生检索请求，例如关键词与数据库范围
         ↓
④ Harness 检查调用参数与权限，交给检索工具
         ↓
⑤ 工具返回记录或错误；Harness 把结果加入后续上下文
         ↓
⑥ 模型依据结果回答、修正检索，或继续请求工具
```

**示例**：用户要“了解海浪预测中的机器学习方法”。Agent 先把问题限定为想要的时间范围和任务类型，使用数据库检索，再检查文章标题、摘要和 DOI。若只读到摘要，应标注“基于摘要”；不能把摘要中没有的实验细节补成“全文结果”。

### 7. 多 Agent 分工：什么时候有用？

课件第 17—18 页以文献综述为例，将任务分给检索员、主笔人和监管者：检索员找资料，主笔人组织文本，监管者检查来源和论述，结果再反馈给负责整体任务的角色。它说明复杂任务可以分解、交接和复核，但每个角色仍可能出错；角色越多也会增加信息传递、成本和冲突处理负担。

**例子**：检索员给出一条文献记录；写作者引用其结论；审核者发现 DOI 对应的是另一篇文章，就应退回核对。多个 Agent 重复同一个未经验证的错误，仍不等于独立证据。

### 8. Model、Tool、Skill、Workflow 的区别

课件第 19 页将这些概念并列，最容易混淆的是“能力”“调用”和“步骤”：

| 名称 | 主要回答的问题 | 示例 |
| --- | --- | --- |
| Model | 如何理解当前信息并生成下一步？ | 生成检索关键词或总结证据 |
| Tool | 系统能执行什么具体操作？ | 调用检索接口、读取文件 |
| Skill | 这个任务有什么可复用的方法和资源？ | 一份文献检索、筛选和核引的操作说明及脚本 |
| Workflow | 任务通常按什么步骤和分支完成？ | 检索 → 筛选 → 阅读 → 整理 → 核验 |
| Harness | 如何把模型、工具、状态和权限组织起来运行？ | 执行工具请求并保存过程 |
| Agent | 如何围绕目标选择与执行行动？ | 多轮检索，遇到问题调整，最后报告 |

**区分**：Skill 可以包含步骤、脚本和资源；Tool 是可调用的具体能力；Workflow 则描述步骤组织。不同产品对这些词的实现和边界可能不同，不能把课堂表格当成唯一技术标准。

### 9. 工具失败时怎么办？

课件第 20—22 页用“网络搜索失败，考虑调用 API”说明：工具报错后，可以检查参数、确认权限和网络，再根据任务与可用能力选择其他来源；不是遇到错误就虚构结果，也不是无条件无限重试。

**API 是什么？** 应用程序编程接口（API）是系统之间按照约定请求和返回数据的方式。例如，数据库 API 可按关键词返回论文题名和标识符。但有 API 不代表必然可用：可能存在权限、费用、限流、覆盖范围或格式限制。切换来源后也要记录实际使用的数据库、检索条件和失败情况。

**理解检查**：检索工具返回“没有结果”和工具返回“请求失败”是一回事吗？

<details><summary>参考思路</summary>

不是。“没有结果”是在某次成功查询下未找到匹配记录；“请求失败”说明没有取得可靠查询结果。两者都不能直接证明相关论文不存在。
</details>

## 四、Agent 的运行循环与工作流（第 23—26 页）

### 10. 一次模型调用如何变成多步任务？

课件第 23 页描述的 Harness 循环可概括为：准备任务和工具信息 → 调用模型 → 判断是回答还是工具请求 → 如有工具请求则执行并返回结果 → 继续调用模型或结束。过程中还应处理权限、次数、时间、失败和需要人工判断的情况；达到限制时报告进度。

这里“多轮”不等于模型永久记住一切。每一轮能看到什么，取决于运行框架组织的上下文、记录和限制；长任务可能需要摘要、检查点或外部记录，但这些机制的可靠性也要检查。

### 11. ReAct：推理、行动、观察

课件第 24—25 页用 ReAct 描述三者交替：

1. **推理／决策**：基于现有任务和信息，决定下一步需要做什么。
2. **行动**：调用一个可用工具，例如数据库检索。
3. **观察**：读取返回结果或错误，再决定继续、修正或回答。

**示例**：需要确认某论文是否存在 → 用题名检索 → 观察返回记录与 DOI → 发现年份不匹配 → 重新查证 → 报告正确记录或说明仍未确认。关键是根据工具返回的信息调整下一步，并留下可检查的行动、来源和结果。

**外部补充**：ReAct 原论文研究将推理轨迹与行动交替，利用外部环境反馈；论文报告的效果来自其具体实验任务，并不保证所有 Agent 都准确，也不要求所有系统都采用同一种循环。[3]

### 12. Workflow 和 Agent 的区别

课件第 26 页的对比：

| 方面 | 预先编排的 Workflow | Agent 运行循环 |
| --- | --- | --- |
| 下一步如何确定 | 更多由事先写好的步骤和分支决定 | 在允许运行的工具、规则范围内，模型可依据观察选择下一步 |
| 例子 | 搜索失败就走指定数据库，成功后保存 | 模型查看失败原因，选择可用的下一种检查方式 |
| 优势 | 路径清晰、容易审计 | 对未预见的中间情况可有更灵活的决策 |
| 注意 | 遇到未覆盖情况可能需要人工调整 | 决策和工具调用可能出错，需要边界与检查 |

二者经常结合：一个工作流中可以嵌入 Agent，Agent 内也可以调用固定流程。因此差异主要是**哪些步骤预先规定、哪些留给运行时选择**，不是两个完全互斥的产品类别。

**理解检查**：如果课件中的网络搜索失败，Agent 什么时候才适合尝试另一个 API？

<details><summary>参考思路</summary>

应先确认该 API 与任务相关、确实可用且有相应权限，并记录失败与新查询的范围；如果无法访问，应如实报告，而不是编造结果。
</details>

## 五、DeepSeek Harness 与课程演示（第 27—32 页）

### 13. Harness 如何支持智能体持续工作？

课件第 27 页以 Cordis 内核、插件能力和配置组合作为例子，展示 Harness 如何为 Agent 提供运行支持：组织模型与工具的交互、管理任务过程，并通过配置组合所需能力。

### 14. 课件中的四种模式

课件第 28 页介绍 DeepSeek Harness 的四种预设模式：

| 模式 | 课件中的定位 | 理解时抓住什么 |
| --- | --- | --- |
| 标准模式 | 用较完整的工具组合完成日常任务 | 预先配置一组常用能力 |
| PTC 模式 | 用一段代码组织多步工具调用 | 减少把每个步骤都单独交互式调用的需要；能否使用取决于配置 |
| 极简模式 | 用少量基础工具 | 能力范围较小，便于特定测试或最小环境 |
| 创造模式 | 检查运行环境、试验插件并形成可复用预设 | 把目标、工具、流程和配置组织成以后能复用的组合 |

DeepSeek Harness 采用插件化架构；其官方项目标注为开发者预览，具体模式和界面可参照所用版本的文档。[4][5]

### 15. “创造模式”是在做什么？

课件给出一个概念性流程：选择可用的模型与工具 → 描述目标、流程和交付物 → 检查运行环境并试验 → 保存为预设 → 用小任务检查能否复用。可以把**预设**想成保存下来的配置组合，而不是另一个自动训练好的科学模型。

课件举了“文献综述智能体”作为提示词示例：目标是检索、提取证据、组织内容并核验引用；实现时还必须具体说明检索范围、来源、允许的操作、输出格式和停止条件。

**操作思路**：先确认模型、工作区和所需工具，再从小任务开始检查调用记录与输出，逐步完善预设。

### 16. “复现 AI Scientist”该怎样理解？

课件第 29—32 页展示以 DeepSeek Harness 组织科研预设：配置技能、组织提出假设／运行代码与实验／绘图／撰写与评审等环节，并强调记录指标和证据。这里应区分三个层次：

1. **学习流程**：理解原论文的任务划分和信息流。
2. **搭建类似工作流**：按可用工具构造一个功能相近的演示或预设。
3. **研究结果复现**：在明确代码版本、数据、模型、算力和评估条件下重做实验，核对实际结果。

检查点用于记录任务进行到哪一步，便于中断后继续；证据账本用于记录主张、对应来源和核查状态。两者共同帮助研究过程追溯：当结论需要复核时，可以回到具体数据、实验与文献。[1]

## 六、与前两讲串起来：可信科研任务如何交给 Agent？

前两讲回答：神经网络通过数据、损失与优化训练；科学建模先明确目标、样本、表示、规模、先验与交付。本讲增加了一个执行层面：如何让系统在权限和工具范围内分步骤完成任务。

**示例：为海浪预测构思一次资料调研**

| 环节 | 应先回答什么 | 可以由系统协助什么 |
| --- | --- | --- |
| 科学问题 | 预测未来波高，还是解释海况变化？ | 将问题拆成可检索的概念 |
| 数据与验证 | 站点、时间、标签、外推目标是什么？ | 对已有描述提出缺失项，不虚构数据 |
| 检索 | 时间范围、数据库、纳入标准是什么？ | 生成检索式、查找记录、列出 DOI |
| 阅读 | 摘要还是全文？方法和结果在哪一节？ | 提取有定位的原文信息并归纳 |
| 判断 | 来源是否匹配、实验和结论边界是什么？ | 组织对照表和待核验问题 |
| 交付 | 要笔记、证据表还是研究建议？ | 保存带来源和不确定性的草稿 |

1. Model、Tool 和 Harness 各自在一次文献检索中承担什么？
2. 为什么说“Agent = Model + Harness”是有用的教学简化，而不是普遍的严格定义？
3. API 查询失败和成功查询但没有记录，下一步报告有什么区别？

5. 固定 Workflow 和运行时 Agent 决策是否可以放在同一系统里？
6. 课件展示了科研预设，为什么不能据此说已经复现 AI Scientist 的实验结果？
7. 如果要把科研数据交给 Agent，你会怎样说明目标、可访问范围和结果验证方式？

<details><summary>参考思路</summary>

1. 模型生成判断或请求，工具执行检索，Harness 组织调用和结果反馈；具体产品分工可有差异。
2. 真实系统还涉及工具、环境、目标和多种实现方式，课堂公式是帮助理解的概括。
3. 失败表示未取得可靠结果；无记录只说明该次成功查询未找到匹配项，二者都不能证明相关工作不存在。
4. 可以是搜索记录、运行输出或报错；外部信息可能错误、过时或不完整。
5. 可以；工作流可调用 Agent，Agent 也可执行固定子流程。
6. 还需明确版本、数据、实验和评估，获得并核对实际结果。
7. 写清任务、允许访问的数据、工具权限、停止条件、来源记录和人工复核要求。
