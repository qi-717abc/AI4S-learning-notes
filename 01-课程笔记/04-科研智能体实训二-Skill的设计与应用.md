## 一、从科研任务看 Skill 的价值（第 2—5 页）

### 1. Skill 能帮助处理哪些重复任务？

课件以图表绘制和样式优化为例：研究者可能反复进行数据整理、绘制图表、调整坐标、标注和导出文件。如果每次都从头描述自己的要求，就容易遗漏细节。将可复用的步骤、规则或模板放入 Skill，可以让智能体在同类任务中参考。

文献调研也有类似特点：从研究问题出发，需要检索数据库、筛选文章、阅读材料、整理证据，最后形成笔记或报告。每一步可能使用不同工具，还需要说明检索范围、来源、筛选依据与输出格式。

可以把这个过程理解为：

```text
研究问题 → 收集信息 → 阅读与比较 → 整理知识 → 形成新的问题
```

一份文献清单主要回答“找到了什么”；一份有用的学习笔记还要解释“这些研究讨论什么、方法如何不同、对问题有什么启发”。Skill 的作用是帮助把需要反复执行的方法整理下来，让智能体在后续任务中使用。

### 2. AI 和研究者怎样分工？

课件将这一分工概括为“AI 来干活，人来判断”。这里的“干活”可以包括检索、初步归类、提取和排版；研究者则明确问题、判断资料是否适合、理解结果并决定下一步。实际分工由任务、系统能力及用户授权决定。

**示例**：研究者想了解“神经网络用于海浪预报有哪些方法”。AI 可以帮忙列出关键词和候选论文；研究者需要判断自己想研究的是预测时效、极端海况、站点泛化，还是其他问题，再决定哪些论文真正相关。

**想一想**：为什么“找 100 篇论文”不等于“回答了研究问题”？

<details><summary>参考思路</summary>

数量说明收集到的记录规模，回答问题还需要筛选、阅读、比较研究设计与结论，并说明这些证据和问题的关系。
</details>

## 二、Deep Research：先把需求变成可检索的问题（第 6—11 页）

### 3. Deep Research 是什么？

课件中的 Deep Research 指借助智能体和工具完成较深入的资料调研，其流程可以概括为：**明确需求 → 收集信息 → 整理并生成结果**。实际系统中可能多次往返：初步搜索发现研究主题过宽，便重新拆解问题并继续检索。

与“一次性提问得到回答”相比，多步调研强调：先确定范围，再带着具体子问题寻找资料，并将结论与来源对应起来。这里的“深”体现为任务拆解、证据收集和比较分析，而不是单纯让回答变长。

课件提到 OpenScholar 相关研究。Asai 等提出利用检索增强模型从科学文献中寻找相关内容，并生成带引用的回答；其目标之一是改善科学文献综合中的来源与内容对应。[1] **检索增强生成（RAG）**的基本思路是先找到相关外部信息，再把其作为生成回答的依据。

### 4. 把宽泛需求拆成研究问题

课件第 9—11 页以“调研近五年的高分子材料研究热点”为例。这个要求听起来清楚，但仍有很多选择：关注哪些材料和性质？“热点”是论文数量、引用、应用进展，还是专家关注？需要综述、论文清单还是研究建议？

可以分三步处理：

1. **复述目标**：用自己的话说明准备回答的问题。
2. **明确边界**：确定对象、时间、关注指标、用途和资料类型；存在重要歧义时与用户对齐。
3. **拆分子问题**：把大问题分成若干可以独立检索和比较的问题，并说明它们怎样共同回答总问题。

**示例：海浪预测文献调研**

| 子问题 | 为什么要问 | 可能的资料或输出 |
| --- | --- | --- |
| 常见预测目标和时间尺度是什么？ | 明确模型要输出什么 | 波高、波周期、预测时效等任务表 |
| 数据有哪些来源和结构？ | 判断输入信息与可用性 | 浮标、再分析资料、网格场等分类 |
| 常用模型及其输入是什么？ | 理解方法之间的差异 | 时序模型、时空模型及对应输入 |
| 研究如何划分训练与测试？ | 理解评价能否对应未来使用 | 按时间、站点或区域划分的比较 |
| 论文指出了哪些难点？ | 找到值得继续追问的问题 | 极端海况、跨区域迁移等问题清单 |

这些是帮助思考的子问题；实际范围取决于研究目标和可用证据。与第二讲的[[六类科学数据的样本结构与划分]]联系起来，调研模型效果时也要看样本、数据结构和切分方法。

**理解检查**：为什么在调研前要问清“结果用于课程学习、研究选题还是系统综述”？

<details><summary>参考思路</summary>

用途决定深度、覆盖要求、检索与筛选方式。课程入门可以做定向阅读；系统综述则需要更严格和可复现的检索、筛选及报告方案。
</details>

## 三、MCP 和 Skill：连接能力与组织方法（第 12 页）

### 5. MCP 是什么？

**MCP（Model Context Protocol，模型上下文协议）**是一套标准化连接方式，帮助 AI 应用与外部能力交换信息。可以把它理解为对“应用怎样发现和使用外部能力”的约定：某个 MCP 服务可能提供工具、资源或提示模板，具体提供什么取决于该服务的实现。[2]

例如，一个实现了文献查询能力的 MCP 服务，可以让支持 MCP 的应用发出查询并读取返回记录。MCP 是连接和交互的协议，**不是数据库本身**；有 MCP 也不意味着一定连接了 OpenAlex、Crossref 或其他特定服务。

### 6. Skill 是什么？

**Skill（技能）**是一组围绕特定任务的可复用说明和资源。它可以告诉智能体：何时适合使用、做事时关注什么、需要读取哪些参考资料、输出应该包含什么。Skill 可以很短，也可以根据需要附带脚本、参考文件或模板。[3]

| 概念 | 主要解决什么问题 | 文献调研示例 |
| --- | --- | --- |
| Model | 理解当前信息并生成下一步内容 | 提出检索词、比较摘要 |
| Tool | 提供一个具体操作 | 搜索数据库、读取 PDF |
| MCP | 用统一协议连接服务提供的能力 | 连接实现文献查询的外部服务 |
| Skill | 保存可复用的任务方法、规则和资源 | 规定如何拆解问题、筛选与记录来源 |
| Workflow | 组织步骤和分支 | 问题拆解 → 检索 → 阅读 → 整理 |
| Harness | 协调模型、上下文、工具和运行过程 | 调用工具并将结果反馈给模型 |

**示例**：你希望调研某个科学问题。Skill 可以指导“先明确对象、时间和输出，再拆分子问题”；检索工具负责实际查询；如果该工具通过 MCP 提供，MCP 负责应用与服务之间的连接方式。三者彼此配合，但职责不同。

### 7. Skill 和一次提示词有什么区别？

一次提示词表达**当前这项任务**，例如“根据这份课件整理第四讲”；Skill 适合保存**重复任务中稳定有用的做法**，例如“先分析课件、列出大纲、再检索补充资料”。这不是绝对的技术边界：两者都可能包含文字说明，差别主要在组织、发现和复用方式。

**理解检查**：装了一个文献调研 Skill，是否就一定拥有某数据库的访问权限？

<details><summary>参考思路</summary>

不一定。Skill 说明如何做事；数据库访问还取决于是否有相应工具、服务、网络和权限。
</details>

## 四、Skill 的结构、内容与调用（第 13—15 页）

### 8. 一个 Skill 里通常有什么？

```text
skill-name/
├── SKILL.md       必需：描述与主要工作说明
├── scripts/       可选：重复使用的辅助脚本
├── references/    可选：按需读取的参考资料
└── assets/        可选：模板、图片等素材
```

按照 Agent Skills 格式，最基本的 Skill 是含有 `SKILL.md` 的目录；其他目录按任务需要添加。[3] 例如，一个只需要指导写作步骤的 Skill 可以只有 `SKILL.md`；如果反复要进行可靠的格式转换，才可能需要脚本。

### 9. SKILL.md 怎样告诉系统“何时用、怎样用”？

`SKILL.md` 常由两部分组成：顶部是 YAML 元数据，正文是 Markdown 说明。最小示意如下：

```markdown
---
name: study-question-helper
description: 帮助将课程中的宽泛研究问题拆解为可检索的子问题。
---

# 研究问题拆解

先理解用户目标与范围，再按需要整理子问题；
每个子问题说明其与总问题的关系和可能需要的信息。
```

- `name`：技能名称。Agent Skills 规范对长度、字符及目录匹配有具体要求。[3]
- `description`：说明技能做什么、什么时候适用，帮助系统识别任务与技能的关系。
- 正文：给出真正有助于完成任务的工作步骤、判断原则和输出要求。

课件第 14 页把一个示例文件分为**元数据、工作流程和输出格式**。输出格式是该示例中的组织方式，应依据任务需要设计，而不是所有 Skill 都必须采用同一套标题。

### 10. 渐进式披露：先发现，再读取细节

当系统有许多技能时，不必一开始把所有 Skill 的全部说明都放进上下文。课件第 15 页展示的流程是：

```text
用户提出任务
   ↓
系统根据可用技能的名称和描述识别候选技能
   ↓
读取匹配技能的 SKILL.md
   ↓
需要时再读取 references、使用脚本或模板
   ↓
结合当前任务与权限执行，整理结果
```

这种分层加载方式称为**渐进式披露**：先使用精简信息做发现，再按实际任务读取详细材料。[3][4] 具体产品的发现和触发方式可能不同；用户也可以在支持该功能的环境中明确指定要使用的技能。

### 11. 用你已创建的 Skill 理解结构

你目前用来处理本讲课件的 `ppt-to-study-notes`，就是一个贴近本课程的例子：

- **触发任务**：根据提供的课件整理 AI4S 学习笔记。
- **主要说明**：先读仓库规则和相关笔记，再检查课件、展示大纲、检索补充资料、写作和检查。
- **输出**：适合在当前 Obsidian 仓库阅读的 Markdown 学习笔记。
- **具体任务**：本次由用户给出第四讲 PDF；同一套 Skill 方法可以用于后续课件。

在这个例子中，Skill 保存的是可复用的工作方法；每次课件的具体主题、页码和补充来源由当前材料决定。

**理解检查**：为什么不建议为了“看起来完整”给每个 Skill 都建立 scripts、references 和 assets 目录？

<details><summary>参考思路</summary>

这些目录各有用途；如果任务只需要简短说明，空目录不会增加能力，反而增加维护负担。
</details>

## 五、课堂实操：从问题拆解到一个可复用的 Skill（第 16—26 页）

### 12. 课堂示例解决了什么？

课件展示了在智能体界面中创建“问题拆解” Skill 的过程。其目标是将范围较宽或描述模糊的问题，整理成更清晰、可以进一步检索的子问题。第 22—24 页的示例结构包括：复述原问题、转述并对齐理解、拆成子问题及说明各子问题的作用。

课件中的示例设计了“先对齐、再拆解”的交互；这是一种 Skill 工作流设计。实际任务中是否必须等待确认，应依据用户要求、任务的重要歧义和当前工作方式确定。

### 13. 为什么“拆得更细”不等于“拆得更好”？

好的子问题应共同服务于总问题，并且能够指导下一步查资料或分析：

- **清楚**：对象、时间和想比较的内容尽可能明确。
- **有关联**：能说明它为什么有助于回答总问题。
- **有分工**：几个子问题各自提供不同信息，不必大量重复。
- **可调整**：查到新信息后，可以补充、合并或重新定义。

**示例**：若总问题是“未来 6 小时海浪如何预测”，只问“有哪些 AI 模型”过于窄；还可以补充“哪些观测在预测时实际可用”“训练和测试是否按时间与站点划分”“何种误差对使用者重要”。这样，检索得到的信息更容易支持模型选择和评价。

### 14. 一个 Skill 从想法到复用

课件中的过程可以理解为：

1. 选择一个**反复出现且值得规范**的任务，例如拆解研究问题。
2. 描述何时使用、输入是什么、希望得到什么输出。
3. 将关键步骤写成 `SKILL.md`；只在需要时加入示例、脚本或资料。
4. 使用一个小任务测试：能否识别需求？输出是否帮助解决问题？
5. 根据实际使用中的问题修改，再用于后续任务。

Skill 是方法的载体；其效果还依赖任务描述、模型能力、可用工具和输入资料。不同环境的安装、发现和调用方式应参考各自文档。

## 六、智能体从哪里获取科研信息？（第 27—32 页）

### 15. 三种信息来源各有什么特点？

| 信息来源 | 作用 | 使用时要看什么 |
| --- | --- | --- |
| 模型已有知识 | 快速解释概念、提出关键词和初步框架 | 可能过时或记错；不等于实际查询数据库 |
| 联网搜索 | 发现网页、论文页面和近期线索 | 搜索摘要只是片段，需要打开来源核对 |
| 数据库或学术 API／MCP 服务 | 获取较结构化的论文、作者、机构等记录 | 覆盖、字段、更新和权限随数据库及服务而异 |

课件第 28 页用表格比较这三类来源。模型可以帮助组织信息；网页和数据库能提供可追溯记录；读者仍需要将具体论述与原始来源对应起来。

### 16. OpenAlex 与 Crossref 分别适合做什么？

课件第 31 页将两者作为文献检索例子：

- **OpenAlex** 是开放学术知识图谱，可组织作品、作者、机构、来源等实体及其关联，适合发现文献和探索引用关系。[6]
- **Crossref** 以 DOI 及其注册元数据为重要内容，可查询题名、作者、期刊和发表信息等，用于核对题录和文献身份。[5]
- **DOI** 是数字对象标识符；可以利用它定位和核对一条记录，但题录信息齐全并不等于已经读过全文或证实报告中的每一个结论。

同一篇论文在不同来源里的字段可能缺失或有差异。核对时可以先比较 DOI、题名、作者和年份，再回到论文或可靠的原始记录检查具体结论。Crossref 主要提供元数据；是否有可访问全文取决于具体记录和出版方。[5]

### 17. “没检索到”能说明什么？

课件第 32 页展示了将已有论文记录与新的检索候选进行比较的界面。一个记录未出现在某次结果中，可能与检索词、时间范围、排序、检索上限或数据库覆盖有关。因此：

- **检索未命中**：这次查询结果中没有出现该记录。
- **DOI 或记录核验失败**：依据指定标识符和来源未取得匹配结果，还需检查输入及来源。
- **结论未被支持**：即使论文存在，也要看原文是否支持报告中的具体说法。

这三个问题需要分别检查。用户给出一个 DOI 时，可以先核对是否对应预期文献，再区分自己读到的是题录、摘要还是全文。

## 七、寻找 Skill 与 MCP（第 33—40 页）

### 18. 从任务出发选择资源

课件提出练习：尝试整理“报告生成”环节的 Skill；之后展示了魔搭社区中的 Skill 与 MCP 资源，以及文献调研和图表绘制等例子。选择时可以先问：

1. **任务是否匹配？** 它解决的是找文献、生成报告、绘图，还是其他问题？
2. **输入和输出是什么？** 是否与你手里的材料、期望的笔记或图表一致？
3. **需要什么工具和环境？** 是仅提供说明，还是还要脚本、API、软件或联网？
4. **来源与维护状态如何？** 看说明、实际文件、版本和所需权限。
5. **如何验证效果？** 先用小任务查看引用、文件和结果是否符合要求，再决定是否长期复用。

课件展示的“Nature Skill”属于绘图与写作等用途的资源示例；理解其能力时应看具体项目说明，不能仅凭名称判断其作者、与期刊的关系或生成结果是否符合投稿要求。

### 19. 报告生成 Skill 的设计思路

将文献调研结果转为报告时，可以设计如下流程：

```text
研究问题与范围
   ↓
核对已收集的文献记录与阅读范围
   ↓
按主题归纳方法、发现和分歧
   ↓
让每项重要论述能回到对应来源
   ↓
组织报告结构并列出待解决问题
```

示例输出可以包含：研究问题、检索范围、主题综述、不同方法的比较、值得继续追问的问题和参考资料。对同一问题使用哪种结构，应由实际任务和材料决定。

## 八、课程回顾与自测

本讲可用一句话串联：**先明确要解决的研究问题，再用 Skill 组织可复用的方法，通过工具或 MCP 获取所需信息，最终把知识与来源整理成可阅读、可核查的结果。**

1. MCP 和 Skill 在文献调研中分别承担什么作用？
2. `SKILL.md` 的 `name`、`description` 和正文分别有什么作用？
3. 什么是渐进式披露？为什么有助于管理多个技能？
4. 为什么论文未出现在一次搜索结果中，不能直接断定它不存在？
5. OpenAlex 和 Crossref 的记录能帮助核对哪些信息？要判断论文是否支持一项具体结论，还需要什么？
6. 用自己的话说明 `ppt-to-study-notes` 中哪些内容属于可复用方法，哪些由本次第四讲决定。

<details><summary>参考思路</summary>

1. MCP 规定应用与外部能力连接和交互的方式；Skill 保存可复用的任务方法与资源。
2. 名称标识技能，描述说明用途与适用时机，正文提供完成任务的指导。
3. 先用简短信息发现技能，需要时再读取详细说明和资源。
4. 结果受查询词、范围、排序和数据库覆盖等影响。
5. 可以核对题录与标识符；具体结论需要回到可获得的论文内容及其上下文。
6. 分析、检索、写作和检查流程可复用；课件大纲、页码和本讲资料由当前 PDF 决定。
